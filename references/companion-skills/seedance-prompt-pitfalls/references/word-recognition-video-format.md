# 单词认知视频格式（轻松学英文 style · 2026-08-21 实测）

> 用户发来参考视频（49s 竖版 720x1048），要求复刻同款。这是**领读绘本的简化兄弟格式**，不是新 skill，并入本 skill 作为参考。

## 格式特征（跟领读绘本的区别）

| 维度 | 领读绘本 | 单词认知视频（本格式） |
|------|----------|------------------------|
| 每页 | 核心词 + 完整句子旁白 | **只有单词**，无句子 |
| 顶部文字 | 英文 + 中文（各一行） | **英文重复两遍 + 中文重复两遍**（`pig pig / 小猪 小猪`） |
| 画面 | 叙事场景 | 萌系卡通，1 个主体 + 3 个同类小主体（温馨家庭感） |
| 音频 | 温柔女声领读 | **欢快儿歌节奏**（用户明确要求） |
| 风格 | Eric Carle 拼贴 / 蜡笔手绘 | 萌系卡通（拟人化大眼睛+腮红+微笑） |

**触发词**：轻松学英文、单词认知视频、欢快儿歌、复刻参考视频、`X X / 中文 中文` 两行字。

## 完整工作流（实测跑通）

### Step A · 分析参考视频格式
- `ffprobe` 拿时长/分辨率 → `ffmpeg -vf "fps=1/3"` 抽帧 → `vision_analyze` 多帧确认：每页一个词、顶部两行字、萌系卡通、儿歌节奏。
- 参考视频是**视频播放器截图**时，中央有白色半透明播放按钮（UI 叠加，非画面内容）→ 必须清理（见下方「播放按钮清理」）。

### Step B · 用 dreamina 生成参考图（关键：本格式没有现成绘本图，需自产）
- 每页一张萌系卡通参考图，**顶部两行字**：第一行英文重复两遍、第二行中文重复两遍。
- 命令：`dreamina text2image --prompt="萌系卡通儿童插画，{主体}，圆润车身/造型，微笑表情，大眼睛，粉色腮红，停在{场景}。背景蓝天白云、绿色树木、彩色小房子。画面顶部两行大字：第一行英文 {word} {word}，第二行中文 {中文} {中文}。鲜艳饱和色彩，圆润可爱造型，温馨明亮，儿童早教风格，竖版构图" --ratio=9:16 --model_version=5.0 --resolution_type=2k --poll=60`
- 输出 1440x2560 竖版，正好 9:16，直接喂 seedance。
- **先做 1 张样图给用户确认风格**，风格对了再批量生成剩余 N 张（避免一次性烧积分结果风格不对）。
- 批量生成后 `query_result --submit_id=<id>` 逐个拿 URL → curl 下载到 refs/ 目录。

### Step C · seedance 视频生成（火锅流程）
- 直接喂竖版参考图 + `ratio=9:16`，不写竖屏强制句。
- 段 1 逐图写「上方彩色"{word} {word}"字母（小写），下方彩色"{中文} {中文}"二字，只有两行，禁止第三行」。
- 末尾约束：`无字幕、无Logo、无水印、无背景音乐` + 逐图大小写锁定 + `禁止生成任何额外文字或字符，只保留参考图中已有的文字元素`。
- **先做 1 个 clip 样片（带音频）给用户确认画面+念词**，OK 再批量做剩余 clip。

## 音频铁律（2026-08-21 用户硬性反馈 · 推翻旧"温柔女声"写法）

> ⚠️ **旧写法已废弃**：本文件旧版写「段 5 音频 = 温柔女声念 + 欢快音效」——用户明确否定。**不要领读风格（"太死板了"）、要童声不要女声、要"唱"不要"念"。**

1. **不要领读风格**（用户原话"太死板了"）——要欢快儿歌节奏。
2. **要童声不要女声**——edge-tts 无专门童声，最接近 `zh-CN-XiaoyiNeural`（卡通活泼女声）和 `zh-CN-YunxiaNeural`（可爱男声），需用户试听确认，不能默认。
3. **要"唱"不要"念"**（用户原话"像唱儿歌一样的调"）——**TTS 只能念不能唱**，调音调/语速/音高都出不来旋律起伏，这是技术限制，不是调参能解决的。
4. **欢快儿歌的正确实现**：需要**带人声的儿歌BGM**（已唱好的完整音频）或**音乐生成模型**（Suno/HeartMuLa/MusicGen）。
   - 无 GPU 跑不了本地音乐生成（HeartMuLa/MusicGen 需显卡）。
   - 在线 Suno 需账号+付费，无可用 key。
   - **最靠谱 = 用户提供已唱好的儿歌BGM**，直接做视频音频，画面+儿歌完美匹配。
5. 若用户提供纯音乐BGM（无歌词），童声TTS念词叠上去仍是"念"不是"唱"，达不到儿歌感——需提前告知用户，别默认能成。
6. **先确认 BGM 是"已唱好的儿歌"还是"纯音乐"**，再决定合成方式。判断：ffprobe 时长 + 能量分布（响亮/安静段交替 = 有前奏主歌副歌结构）+ 零交叉率（语音高/纯音乐低）。

## 播放按钮清理（视频播放器 UI 叠加）

参考视频抽帧后，中央常有白色半透明播放按钮（三角形+圆角方块）。它是播放器 UI，不是画面内容，喂 seedance 前必须清掉。

**方法（PIL 环填充 + 高斯模糊，无需 opencv）**：
```python
from PIL import Image, ImageFilter
import numpy as np
img = Image.open('frame.jpg').convert('RGB')
a = np.array(img).astype(np.float32)
h,w,_ = a.shape
x0,x1,y0,y1 = 320,416,540,620   # 播放按钮 bbox（先定位）
for _ in range(3):
    ring = np.concatenate([
        a[y0-12:y0, x0-12:x1+12].reshape(-1,3),
        a[y1:y1+12, x0-12:x1+12].reshape(-1,3),
        a[y0:y1, x0-12:x0].reshape(-1,3),
        a[y0:y1, x1:x1+12].reshape(-1,3),
    ])
    a[y0:y1, x0:x1] = ring.mean(axis=0)
out = Image.fromarray(a.astype(np.uint8)).filter(ImageFilter.GaussianBlur(1))
out.save('ref_clean.png')
```
**定位播放按钮**：中央 200x200 区域找高亮低饱和像素（`sum>600` 且 RGB 通道差 <30）的 bbox。

**⚠️ 陷阱 #16 复现**：清理后视觉模型仍可能报"还有播放按钮"——这是对半透明叠加图标的过度敏感误读。**验证方法**：裁剪按钮区域放大看（`btn_crop.png`），若区域平均亮度 ~179 且无 >200 亮像素 = 已清干净，是视觉模型误读，别重做。用户眼睛是最高权威。
