# 流程内不确认 · 流程外才让用户介入

> **跨 skill 通用元方法论** — 绘本视频 / 漫剧分镜 / 账号运营 / 任何批量输入处理任务
> **首次沉淀**：2026-06-16 picturebook-video skill 沉淀期
> **第 1 次跨本验证**：2026-06-16 爷爷 Grandpa 绘本（v4.0 首秀）
> **第 2-3 次待验证**：需 ≥ 3 次跨场景才能升 SKILL.md 铁律（按元教训 M）

## 核心命题

```
用户给我 N 张图 + 旁白 + TTS
   ↓
我在流程内 = 全跑（vision N 张 / image-inventory / 叙事弧 / 时长 / 5 项必查）
   ↓
流程边界 = 提交方案给用户
   ↓
用户目检 / 反馈 → 我继续
```

**关键区分**：
- ❌ 流程内问用户"我接下来要 vision 几张" / "要不要先写 image-inventory" = **打扰用户** = 反模式
- ✅ 流程边界（"Clip 1 跑完，要不要我连跑剩下 4 个"）= 拍板项 = **问** = 正常
- ✅ 流程边界（"Clip 1 跑完，结果如何"）= 报告 = **不**问 = 正常

## 触发器

读到以下场景立即警觉：

```
"接下来要不要 / 能不能 / 是不是先..."
"我打算 X 因为 Y，你 OK 吗"
"需要我先做 X 还是先做 Y"
```

**判断流程**：
1. 这是流程内还是流程边界？→ 流程内 = **不问** = 全跑
2. 我问的这个问题是不是"询问"伪装成"报告"？→ 是 = 反模式
3. 是不是"怕你不同意"才问？→ 是 = 反正模式

## 决策树

```
用户在流程中问我"要不要 X / 接下来做什么"？
├─ 是 → 一次性报方案（不 = 问 · 是 = 报告）
│       "我打算 X 因为 Y，跑下去 OK"
└─ 否 → 流程内 = 全跑 + 流程边界（= 提交/目检/换方向）= 问

我已经做了 N 步，要不要问"对吗"？
├─ 是 → 流程边界 = 报告（"做了 X / Y / Z · 下一步打算 W"）
└─ 否 → 流程内 = 不回头看 = 继续
```

## 实战对照表

| 场景 | 反模式 | 正模式 |
|------|--------|--------|
| 收到 8 张图 | "我打算分 3 批 vision 你 OK 吗" | 直接 vision 3 批 + 写 image-inventory |
| 写完 image-inventory | "清单写好了，要继续吗" | 继续标叙事弧 + 合并 Clip |
| 写完 prompt | "5 个 prompt 都写好，要提交吗" | 提交 Clip 1 + 报告 |
| Clip 1 跑完 | "Clip 1 OK，要不要连跑剩下 4 个" | 报告时长/md5 + **问**（拍板项 = 流程边界）|
| 5 个 Clip 都跑完 | "全部跑完，要不要发飞书" | 直接发飞书 + 报告 |

## 跟其他元方法论的关系

- **元教训 J 主动追问 = 我对自己问**：内部推理，不打扰用户
- **元教训 N 冲突时降级**：本方法论 = 跟 "superpowers prefer multiple choice" 不冲突（superpowers 推荐的是 brainstorm 阶段列 2-3 方案，不是流程内每步问）
- **元教训 M 反模式不擅自加**：本方法论目前是 references/ 层（跨场景 1 次验证）= **不升 SKILL.md 铁律** = 等 ≥ 3 次跨本验证

### 第 4 次 · 2026-07-19 ear 绘本（picturebook-video · v5.0.16）

**用户原话**（两步连续纠正）：

1. "我直接发给你文件了，你没收到吗？还有，我早就说过了：
   1. 你哪怕使用这个选项给我，最好不要使用这种选项。
   2. 哪怕使用这种选项的方式跟我交付，你也要能接收。
   我其他的消息，我不想只回答你的选项"
2. "难道不是要先识别图片吗？"

**触发场景 A（用户已发文件 + 仍用 `clarify` choices 问"怎么给你"）**：
- 实际：用户发来 `ear.7z`，我立刻问"用选项告诉我路径 / 飞书 / 模板"
- 反模式根因：`clarify` 工具被当成默认开场 — 但**用户已经发了文件** = 文件已经在 cache/documents/ 下 = 任何"在哪给我"的问题都是冗余
- 正模式：直接 `cd` 读 cache，文件已就位 → 跑解压 / 看 SRT / 看图
- 守门：每次会话开头收到任何文件，先 `ls ~/.hermes/profiles/huiben/cache/documents/` 看新文件，**不要**用 `clarify` 反问来源

**触发场景 B（未 vision 就问派生参数）**：
- 实际：Step 1 阶段我先问"画幅比例选 16:9/9:16/1:1"
- 反模式根因：画幅/分镜/角色朝向/风格 这些**全部派生**自图片本身（装饰字位置决定裁切风险、风格决定运镜节奏、角色数决定 clip 划分）→ 没 vision 之前问"画幅" = 拍脑袋
- 正模式：先跑 `srt_parser.py` + vision 8 张 + 写 image-inventory，**所有派生参数**（画幅/clip 数/分镜镜头）从 inventory 倒推出来 → 4 确认点 #1 一次性报告 "我打算 X 因为 Y"（= 报告不是询问）
- 守门：派生参数永远在 vision + srt 解析后报告，不在 vision 前用 `clarify` 问

**用户原话铁律（2026-07-19 拍板）**：

> **"你哪怕使用这个选项给我，最好不要使用这种选项。哪怕使用这种选项的方式跟我交付，你也要能接收。"**

含义（已升为用户级铁律，需在所有 skill 开头遵循）：
- 偏好层 1：`clarify` / `选项` 是**最后手段**（不可逆 / 真正判断不了才用）
- 偏好层 2：哪怕你判断 "用选项效率高"，也要能 **在不依赖选项** 的情况下完成 = 默认路径必须不靠选项
- 偏好层 3：用户已发文件/已给信息 = 任何"在哪给我/什么格式"类问题 = 冗余 = 触发用户反感

**升级判定**：本条目已**撞 ≥ 2 次**（这次 + 2026-06-16 Grandpa），但 picturebook-video 内**第 2 次**，仍按 references 层保留。下次同 skill 触发第 3 次 → 升 SKILL.md 铁律（按元教训 M）。

# 流程内 = 0 问

# 反模式自检
# "我接下来打算 X 因为 Y" 是 = 报告 不是 = 询问
