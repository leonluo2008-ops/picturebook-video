# 多图参考朝向不一致 · 镜头衔接断裂修复

> **来源**: Crane Truck 起重机绘本 2026-07-09 spike v1 翻车 → v2 修复沉淀
> **场景**: 多图 Clip 中，相邻 `@ImageN` 主体朝向不同（最常见 = 朝左 vs 朝右 180 度硬翻，或朝前 vs 朝后）
> **症状**: 镜头切换瞬间画面"断裂"——主体姿态硬切无过渡，seedance 不知道这是设计意图，直接 hard cut
> **根因**: v8.1 R6 段 1 逐图描述视觉基底时，写明了朝向，但 R7 段 2 镜头动作序列没显式说明"如何从 @ImageN 朝向过渡到 @ImageN+1 朝向"

---

## 1. 真实案例（Crane Truck Clip 1 spike v1）

**素材实情**（已 vision 自检）：
- @Image1: 黄色起重机 **朝左**，吊臂伸展指向画面右上方
- @Image2: 黄色起重机 **朝右**，吊臂伸展
- @Image3: 黄色起重机 **朝右**，吊臂斜上方伸展

**v1 prompt（❌ 翻车）**：
```
镜头 2（@Image2 + 段 2 旁白）：固定镜头，起重机在画面中央轻微左右摇摆，
吊臂缓慢抬起约 15 度，吊钩随惯性轻摆，镜头方向：固定，主体位移方向：原地微摆。
```

**v1 翻车症状**：镜头 1→2 切换瞬间，主体从朝左硬翻到朝右（180 度 hard cut），画面出现"断裂"感。

**v2 prompt（✅ 修复）**：
```
镜头 2（@Image2 + 段 2 旁白）：固定镜头，黄色起重机在画面中央原地缓慢旋转 180 度
（从朝左转至朝右，吊臂边转边轻微抬升 15 度，吊钩随惯性轻摆），
镜头方向：固定中景，主体位移方向：车身原地旋转 180 度，吊钩随转幅画弧线。
```

**v2 修复效果**：把"断裂"显式变成"被设计的旋转过渡事件"——seedance 知道这是有意旋转，画面连续。

---

## 2. 修复手法 3 类（按错位幅度分）

### 2.1 朝向 180 度硬翻（最常见）→ **原地旋转过渡**

```python
# 模板
镜头 N（@ImageN+1 + 段 M 旁白）：固定{景别}，{主体}在画面{位置}原地缓慢旋转 180 度
（从{原朝向}转至{新朝向}，{附带动作}），镜头方向：固定{景别}，
主体位移方向：车身原地旋转 180 度，{细节弧线}。
```

**适用**：朝左 ↔ 朝右 / 朝前 ↔ 朝后 / 朝上 ↔ 朝下
**时长要求**：旋转动画建议 ≥ 2s 才不显得生硬（绘本单镜头 2-4s 节奏）

### 2.2 朝向小角度错位（30-90 度）→ **附带动作遮蔽**

```python
# 模板
镜头 N（@ImageN+1 + 段 M 旁白）：{运镜}，{主体}{附带大动作（如：抬手/转头/转向镜头/侧身坐下）}
过程中自然完成{度数}朝向过渡，镜头方向：{运镜}，主体位移方向：{附带动作方向}。
```

**适用**：转头看向旁边物体 / 侧身拿起东西 / 抬手打招呼
**优势**：比显式旋转更自然（叙事内动作遮蔽朝向变化）

### 2.3 朝向一致但**位置/比例/视角**突变 → **运镜承接**

```python
# 模板
镜头 N（@ImageN+1 + 段 M 旁白）：{运镜（推近/拉远/横移）}，
{主体}从{原位置/比例}过渡到{新位置/比例}，镜头方向：{运镜}，
主体位移方向：{运镜位移方向}。
```

**适用**：@ImageN 全景 → @ImageN+1 特写（推近承接）/ @ImageN 中景 → @ImageN+1 大全景（拉远承接）
**注意**：R11 镜头 4 件套的空间目标必须明确写出

## 3. 修复决策表

| 错位类型 | 检测方法 | 修复手法 | prompt 关键词 |
|---|---|---|---|
| 朝向 180 度硬翻 | vision_analyze 报告 @ImageN "朝左" + @ImageN+1 "朝右" | 原地旋转过渡 | "原地缓慢旋转 180 度"、"转至新朝向" |
| 朝向 90 度错位 | vision_analyze 报告朝向差 1 个方向 | 附带大动作遮蔽 | "过程中自然完成朝向过渡"、"附带动作" |
| 景别/比例突变 | vision_analyze 报告景别差异大（全身→特写） | 运镜承接 | "推近承接"、"拉远承接"、"横移过渡" |
| 背景色调突变 | vision_analyze 报告背景色不一致 | 镜头切换 + 拉镜/推镜掩饰 | "缓慢推镜"、"镜头横移穿越" |

## 4. 预防：vision 自检阶段提前发现

**Step 2 vision 自检 5 项必查**（picturebook-video SKILL.md §2）已包含"主体朝向"。

**新增第 6 项（v5.0.16 实测建议）**：

> **相邻参考图朝向一致性预检**：列出每张参考图的主体朝向（朝左/朝右/朝前/朝后），相邻 Clip 内的 @ImageN 和 @ImageN+1 朝向差异 > 90 度 → 必须在 Step 5 段 2 镜头 N 显式写过渡动作，不能省略。

**实操**：vision 自检输出后，对 Clip 内每对相邻 @ImageN 做朝向对比表：

```
Clip 1:
  @Image1 → 朝左
  @Image2 → 朝右    ← 180 度硬翻 ⚠️ 需写旋转过渡
  @Image3 → 朝右    ← 一致 ✅
```

## 5. verify_prompt.py 不覆盖此问题

verify_prompt.py R6-R10 + R11 都不检查"相邻参考图朝向是否一致"——这是**视觉叙事问题**，不是 prompt 结构问题，脚本无法判断。

**唯一检测手段**：Step 2 vision 自检 + Step 5 段 2 写完后人工扫一遍相邻镜头。

**spike 测试兜底**：v5.0.13 路径 C 单 clip spike 测试是发现此问题的最便宜手段（Crane Truck spike v1 用 1 次失败就抓到了）→ **不要跳 spike 直接批量提交**。

## 6. 跟现有 v8.1 规则的关系

| 规则 | 关系 |
|---|---|
| R6 段 1 逐图描述视觉基底 | ✅ **互补**：R6 写明朝向，本文件教"朝向不一致时怎么办" |
| R7 段 2 镜头段绑定 @ImageN + 段 N 旁白 | ✅ **互补**：R7 强制镜头绑定，本文件教"绑定后镜头动作怎么写" |
| R9 段 4 收尾不凝固 | 不相关 |
| R11 镜头 4 件套 | ✅ **应用**：旋转过渡也需符合"镜头方向 + 主体位移方向"格式 |

**v8.1 模板升级建议（不强制）**：在 R7 镜头段后追加子规则——
> 如果相邻 @ImageN 主体朝向差异 > 90 度，必须在镜头 N 段 2 显式写明朝向过渡动作（旋转/附带动作/运镜承接），不可省略。

本规则是否升级到 verify_prompt.py 硬规则（FAIL 级）→ **不在本次沉淀范围**（按 user profile "严禁自作主张沉淀规则"原则，需用户明确授权）。

## 7. 触发条件速查

**当 vision_analyze 输出中出现以下情况时，本文件立即生效**：

1. 同一 Clip 内相邻 @ImageN 的"主体朝向"vision 报告不一致（朝左 vs 朝右 / 朝前 vs 朝后）
2. 同一 Clip 内相邻 @ImageN 的"景别"差异大（全身 → 特写）
3. spike 测试发现镜头切换瞬间有"断裂"/"硬切"感
4. 用户反馈"镜头 X 切到镜头 Y 时不流畅"
