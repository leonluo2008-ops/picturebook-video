> **原则（user profile）**: 严禁自作主张改脚本 / 严禁自作主张沉淀规则 → **用脚本认识的词，最小改动原则**

## 1. 真实案例（Crane Truck Clip 1/2/4 v1）

- "向画面**上沿**延伸" ← `上沿` 不在表里
- "接近**顶部边缘**" ← `接近顶部` 不在表里
- "从画面**下沿**升起到中部" ← `下沿` 不在表里


**verify 通过**：R11 FAIL 消除

## 4. 何时该改脚本 vs 何时改 prompt

### 改 prompt（默认 · user profile 原则）

**触发条件**：
- 写的空间目标在语义上能用脚本认识的词等价表达
- 是 prompt 写法偏好，不是脚本规则错误

**操作**：
- 查 `space_keywords` 表 → 找到等价词 → patch prompt
- 1-2 处修改，不动其他结构

### 改脚本（需用户明确授权 · user profile "严禁自作主张"）

**触发条件**：
- 写的空间目标**语义上无法用现有词等价表达**（如 "从画面外缘沿对角线穿越到对面外缘"）
- 多个 prompt 反复遇到同一缺口 → 说明表是真的不全

**操作**：
- 报告用户 → 等用户明确授权 → 才修改 scripts/verify_prompt.py
- 修改时同时跑双向测试（旧 prompt FAIL + 新 prompt PASS）→ 元规则要求

### 不该做的

- ❌ **不要**绕过 verify_prompt.py 直接提交（违反 v5.0.16 R5.5 强制）
- ❌ **不要**默默改脚本不告知（违反 user profile "严禁自作主张沉淀规则"）
- ❌ **不要**用 "WARN 不阻断" 当借口忽略 FAIL（FAIL 是硬规则，必须消除）

## 5. 与 v5.0.16 硬约束 #6 的关系

**硬约束 #6（v5.0.16 新增）**：镜头 4 件套 = 运镜 + 主体动作 + 位置空间变化 + 音频信息

**位置空间变化** 是硬约束的三大要素之一（脚本 R11 强制 FAIL 级）。

**本文件的立场**：
- ✅ 脚本硬规则有价值，不绕过
- ✅ 最小改动原则 = 改 prompt 用脚本认识的词，不动脚本
- ⚠️ 词表确有缺口时，**报告用户**而非自行扩容

## 6. 跟"最小改动原则"的一致性

**picturebook-video SKILL.md §5 反模式根因诊断 · 6 个之一**：
> "过度展开提示词"（2026-06-30 See You 实测）：读完官方文档后把每个镜头的动作描述过度展开（加主体定义块、动作过渡衔接、程度量化、情绪外化等） → 提示词过长违反简洁规定 → 正确做法是**最小改动原则**：只替换有问题的部分，不动已经稳定的结构。

本文件是"最小改动原则"的**实战应用案例**：
- 不改脚本（脚本是稳定结构）
- 不改 prompt 已稳定的视觉基底段 1
- 只替换空间目标的 1-2 个词（最小改动）
- 保留 R6/R7/R8/R9/R10 段结构不变

## 7. 应急检查清单

如果 verify_prompt.py 报 `FAIL R11: 镜头 N 缺空间目标`：

1. **检查段 2 镜头 N 文本** → 找出"主体位移方向"那一句
2. **比对 `space_keywords` 表**（本文 §2）→ 找出不认识的词
3. **查表 §3 常见近义词对照** → 选最接近的等价词
4. **patch prompt**（最小改动，只改 1-2 个词）
5. **重跑 verify_prompt.py** → 确认 FAIL 消除
6. **如果表中确实没等价词** → 报告用户 → 等授权决定是否扩表
