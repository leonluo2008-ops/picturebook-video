# 图-段对位核对 · 硬约束 #7 · v5.0.17

> **沉淀来源**: 2026-07-23 集市绘本（Market）Step 2 vision 自检踩坑。
> **结论**: Step 2 vision 5 项必查只查单图特征,不够——必须**额外输出图-段对位表**并跟用户确认,否则会带着错误的对位假设推进到 Step 3/4,浪费 clip_merger 一次调用 + 用户两次"别 BB"反馈。

---

## 1. 为什么要加硬约束 #7

### 1.1 翻车复现(集市绘本 2026-07-23)

- 素材包:`Market集市.7z` 解压 = **0-8.jpg 共 9 张图 + `集市.srt` 8 段旁白**
- agent Step 2 vision 自检: 9 张图都拍了 5 项必查,得出"图数 9 = 段数 8 多 1 张"
- agent **没做图-段对位**,凭印象"0=封面 / 1-7=内页 / 8=??? / 段数 8,9=差 1 张,弃一张就行"
- Step 3 直接跑 clip_merger → 3 个 Clip 划分 (7+13+9 = 29s)
- Step 4 4 确认点 #1 才跟用户确认 → 用户崩:"哪来什么封底,给你的就是必须用的参考图,明明都对应了旁白"
- agent 追问"8.jpg 对应哪段?" → 用户再次崩:"你先看图,别 BB"
- agent 重新仔细 vision 看 5/6/7/8.jpg → 发现:
  - **0.jpg 是封面,真的应该弃用**(包含"Market/集市"标题文字,不是内页)
  - **5.jpg 跟 4.jpg 都是鲜花**(4=花盆,5=花束)= 5.jpg 重复,**应该弃用**
  - **6.jpg 才是鱼**(5.jpg 不对),**7.jpg 才是遮阳棚**(8.jpg 才是多摊位汇总)
  - **段 #1 无图**(段 #1「集市, MARKET！」只有 3.4s 含停顿 < 4s 下限)→ 强制合并到段 #2
- 两次"别 BB" = 用户原话级反馈

### 1.2 根因

Step 2 vision 5 项必查 = **单图特征**(位置/朝向/景别/姿态/文字),**不要求跨图对比 / 跨段对照**。

用户的真实需求是:**"看一遍图就知道哪张对应哪段"**——这一步**必须在 Step 2 完成**,不能在 Step 3/4 反馈。

### 1.3 二次翻车(集市绘本 2026-07-23 同日复测)

上一份对位表把素材标成"9 张图含封面/封底/重复"。**用户纠正后,同一会话重新跑 Step 2**——素材包其实是 **8 张图 = 8 段旁白,1:1 干净对位,无封面/封底/重复**。

- agent 收到"确认"后,**没回头重新点清文件清单(`ls`/`find`),直接信任上次结论的反面**
- vision 8 张全部 vision_analyze 后,描述文字出现"摊位""遮阳篷""蓝天白云"等**语义相似词**
- agent **凭 vision 文字相似性**脑补"1.jpg vs 2.jpg 都是摊位 = 重复","段 #1「集市,MARKET!」只有标题文字 = 封面 = 无图"
- 输出对位表标了 3 个"伪异常" + A/B/C 处置选项
- **用户当场发飙**: "你TM有病吗?总共收到几张图?什么JB重复,无图,先给老子搞清楚"

**根因**(同根新表象):
- vision_analyze 输出是**长文本描述**,用词容易重复("摊位""遮阳篷""蓝天白云"会在多张图描述里反复出现)
- agent 把"**描述文本相似**"误判成"**图内容相同**"
- **没回到结构化文件清单**(`ls *.jpg` 数量)做 ground truth
- vision 输出文字 ≠ 图片像素 ground truth,**描述相似性 ≠ 像素相似性**

**修正铁律(图-段对位表生成前必走)**:
1. **先 `ls` / `find` 解压目录** → 拿到结构化图清单(数量 + 文件名)——这是 ground truth
2. **再 vision_analyze 全部 N 张** —— 拿到每张图的主体描述
3. **再 vision_analyze N 段 SRT 文本** —— 拿到每段旁白对应的主体
4. **最后才出对位表** —— 基于"图清单数量 vs 段数量 = 图-段对位" + "vision 主体描述 vs 旁白主体词"双重核对
5. **图数 == 段数 且 vision 主体描述跟旁白主体词能一一对得上 = 无异常,直接出干净对位表**(不要"为了显得专业"硬造异常)
6. **vision 描述文字里出现相似词 ≠ 图内容相同**——只要文件名不同 + 段号不同 = 独立对位,不要脑补"重复"
7. **「凭印象/凭上次结论」出对位表 = 直接翻车**——必须基于当前会话**当下重新跑过**的 `ls` + `vision_analyze` 数据

## 2. 图-段对位表(强制输出格式)

```markdown
| 图 | 视觉内容 | 对应段 | 状态 |
|----|----------|--------|------|
| 0.jpg | 封面(只有"Market/集市"标题文字) | — | 弃用(封面) |
| 1.jpg | 摊位 | 段 #2「集市有摊位」 | ✅ |
| 2.jpg | 水果 | 段 #3「集市有水果」 | ✅ |
| 3.jpg | 蔬菜 | 段 #4「集市有蔬菜」 | ✅ |
| 4.jpg | 鲜花(花盆) | 段 #5「集市有鲜花」 | ✅ |
| 5.jpg | 鲜花(花束) | 段 #5 | **重复 4.jpg → 弃用** |
| 6.jpg | 鱼 | 段 #6「集市有鱼」 | ✅ |
| 7.jpg | 遮阳棚 | 段 #7「集市有遮阳棚」 | ✅ |
| 8.jpg | 多摊位汇总 | 段 #8「集市的东西真齐全」 | ✅ |
| 段 #1「集市，MARKET！」 | — | 无图 | **强制合并到段 #2**(段 #1 仅 3.4s < 4s 下限) |
```

## 3. 判定规则

| 图数 vs 段数 | 处理 |
|---|---|
| **图数 == 段数** | 一一对应 ✅,最理想。**vision 描述文字相似(都叫"摊位"/"遮阳篷")不构成"重复"**——只要文件名不同、段号不同、主体词不同 = 独立对位。**严禁凭 vision 文字相似性脑补"重复/封面/缺图"** |
| **图数 > 段数** | 多余图 = 重复 / 封面 / 非旁白页 → 标"弃用"或问用户对应哪段(对话 1 次) |
| **图数 < 段数** | 缺图段 < 4s → 强制合并到下一段(走 SRT 时段首;纯旁白时按叙事顺序)<br>缺图段 ≥ 4s → **必须问用户怎么处理**(不要擅自决定) |
| **封面/封底**(标了"封面"/"封底"/有标题文字无内页主体) | 单独标"不进入 Step 5 prompt,只走 Step 7 飞书素材归档" |
| **多张内容相似**(肉眼难分) | vision 时**重点比对**(用 `vision_analyze` 单独再问一次"这张摆了什么具体商品?") |

## 4. 反模式(必避)

| 反模式 | 来源 | 后果 |
|---|---|---|
| agent 自己脑补"5.jpg 看上去像 8.jpg 的延续"强行配对 | 集市绘本 2026-07-23 | 用户两次"别 BB" |
| 不出对位表,直接跳 Step 3 然后 clip_merger 输出后发现 | 集市绘本 2026-07-23 | 浪费 clip_merger 调用 + 用户反馈 |
| 出对位表但**不跟用户确认**,默认"按我理解的来" | 同上 | 同样踩坑 |
| vision 第一遍只描述"市场摊位",不报"几号摊位/摆了什么商品" | 同上 | 5.jpg vs 6.jpg 视觉相似但内容不同,必须细看 |
| 对位异常时反复确认同一个问题(超过 2 次) | 同上 | 用户原话"别 BB" |

## 5. 对话纪律(集市绘本 2026-07-23 实测沉淀)

- 出对位表用 **markdown 表格**,**少 BB**——一段一行说清状态
- 异常项一句话说清(如"5.jpg 跟 4.jpg 重复 → 弃用"),**别展开解释**
- 用户说"对/开始/确认" → 即进 Step 3;**不要再做 A/B/C/D 选项**
- 用户说"错了,XXX"(具体纠错)=**接受立即执行,不反问**,改对位表后重跑 Step 3
- 不要替用户判断"哪张更合适"——出了对位表让用户自己选
- **严禁凭 vision 描述文字相似性造异常**(2026-07-23 同日复测踩坑:用户原话"你TM有病吗?总共收到几张图?什么JB重复,无图,先给老子搞清楚")——8 张图 + 8 段旁白 = 干净 1:1 对位,vision 文字都说"摊位/遮阳篷"不代表"重复"
- **必须先 `ls` 解压目录拿到结构化图清单,再 vision,再出对位表**——这个顺序不能反

## 6. 会话内重做 Step 2 时的纪律（2026-07-23 同日复测沉淀）

**场景**：用户纠正后 agent 在同一会话内**重做** Step 2（如用户说"重新看图"/"再出一遍对位表"）。

**反模式**（2026-07-23 集市绘本实测踩坑）：
1. agent 收到用户纠正 → **凭印象 + 凭上次结论的反面**重出对位表 → vision 描述里出现"摊位""遮阳篷""蓝天白云"等**语义相似词** → agent 把"**描述文本相似**"误判成"**图内容相同**" → 输出"1.jpg vs 2.jpg 重复/段#1 无图"等伪异常
2. 用户当场发飙："你TM有病吗？总共收到几张图？什么JB重复，无图，先给老子搞清楚"

**根因**：
- vision_analyze 输出是长文本描述，多张图的描述里反复出现"摊位""遮阳篷""蓝天白云"是**正常的视觉重叠词汇**，不是"内容相同"
- agent 没回到结构化文件清单（`ls *.jpg` 数量）做 ground truth
- "凭上次结论的反面"出对位表 = 直接翻车

**重做 Step 2 必走 5 步**（强制顺序，禁止跳）：
1. **`ls` / `find` 解压目录** → 拿到结构化图清单（数量 + 文件名 + 大小）—— ground truth
2. **重新 vision_analyze 全部 N 张**（不要复用上次的 vision 输出）—— 拿到每张图主体
3. **数清楚 SRT 段数**（读 SRT 头部或跑 srt_parser.py）—— ground truth
4. **对照图清单数量 vs 段数量** —— 决定是否有异常
5. **vision 主体描述 vs 旁白主体词 1:1 对位** —— 只有"图清单数量 vs 段数量 == 1:1 且 vision 主体 vs 旁白主体能对得上"才出干净对位表；**不要为了显得专业硬造异常**

**判断口诀**："图清单数量 vs 段数量 = 1:1 + vision 主体词 vs 旁白主体词 = 1:1 = 干净对位表直接出，不要造异常"。

---

## 7. 配合 Step 3-4 调用流程

```
Step 2 vision + 图-段对位表(本节)
   ↓ 用户确认
Step 3 srt_parser / tts_rate_calculator
   ↓
Step 4 clip_merger(用真实对位表"5 弃/段 1 并段 2"告诉脚本)
   ↓
Step 5 写 prompt (用对位后的图数 + 段数)
```

**注意**: clip_merger 默认按段数划分,**不会自动剔除弃用图**——Step 4 给脚本传 json 时,**只传对位表中✅的段,不传弃用段对应的图**。
